# App Platform Failure and Interleaving Analysis

- **Status:** Phase 0 proposal
- **Date:** 2026-11-11

This analysis defines the correctness boundaries that Phase 1 and later phases
must test. Process-local locks can reduce duplicate work. They cannot be the
source of truth.

## Common rules

- Durable domain changes use the canonical aggregate OCC boundary.
- Mutable shared state uses JetStream KV revisions and explicit expiry.
- A missing or revoked credential decision is confirmed through the stream
  leader.
- A retry uses a stable logical operation ID and request fingerprint when the
  contract provides a request ID or server-issued capability.
- An external effect is at least once unless the table says otherwise.
- A lost response can cause a retry. Return the first result when the contract
  identifies the retry. Otherwise, document that the retry can create a second
  operation.
- Logs contain machine categories and stable non-PII IDs only.

## OAuth and tokens

| Operation                   | Failure or interleaving                                               | Required invariant and recovery                                                                                                                                                            | Required test                             |
| --------------------------- | --------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ----------------------------------------- |
| Authorization code creation | Two replicas complete the same consent action.                        | One app grant and one code generation win through revision or aggregate OCC. The losing response returns the winning redirect or a conflict.                                               | Concurrent consent completion.            |
| Code exchange               | Two replicas exchange the same code at the same time.                 | One revision-matched claim wins. An exact retry reads the encrypted exchange outcome. A changed client, redirect URI, or verifier fails.                                                   | Concurrent exact and changed exchanges.   |
| Exchange response           | Tokens commit, then the HTTP response is lost.                        | The same code and request return the same token response during the short outcome TTL. No second token generation is created.                                                              | Drop the first response and retry.        |
| Code expiry                 | A request starts before expiry and claims after expiry.               | Expiry is checked inside the claim operation. An expired code never issues a token.                                                                                                        | Clock-boundary exchange.                  |
| PKCE                        | A wrong verifier races a correct verifier.                            | A wrong verifier does not consume the code. The correct verifier can still claim it. Repeated wrong attempts are bounded.                                                                  | Wrong and correct concurrent verifiers.   |
| Client secret regeneration  | An exchange uses the old secret while regeneration commits.           | The aggregate or credential generation decides one order. An exchange accepted before commit can finish. A later request with the old secret fails.                                        | Regeneration/exchange race.               |
| Access-token issue          | App installation is revoked between scope consent and token creation. | The token issue checks the current installation generation in the same guarded operation. No token is issued for a revoked generation.                                                     | Uninstall during exchange.                |
| Token validation            | A lagging replica reads a token that another replica revoked.         | A positive cached read can be stale only within the documented validation window. A rejection and periodic live revalidation use the leader. Revocation publishes a live termination hint. | Cross-replica revoke and immediate call.  |
| Non-rotating token          | Idle time passes.                                                     | The token remains valid until explicit revocation or principal invalidation. No cleanup TTL removes it.                                                                                    | Long simulated idle window.               |
| Refresh rotation            | Two replicas use the same refresh token.                              | One revision-matched consume wins. The loser can receive the winning generation only during the documented grace case; otherwise it gets `invalid_refresh_token`.                          | Concurrent refresh.                       |
| Rotation response           | New tokens commit, then the response is lost.                         | A bounded encrypted rotation outcome returns the same pair for an exact retry. It does not create a third live generation.                                                                 | Lost refresh response.                    |
| Revoke all                  | API calls and Socket sessions use tokens while revocation scans.      | A durable installation generation fence invalidates all old records immediately. Physical deletion is cleanup.                                                                             | Calls during partial cleanup.             |
| IP allowlist                | Source address changes through a proxy or load balancer.              | Trust only configured forwarding headers from trusted proxies. Apply the allowlist to the resolved client address. Never log it raw.                                                       | Trusted and untrusted forwarding headers. |

## App and manifest lifecycle

| Operation                | Failure or interleaving                                              | Required invariant and recovery                                                                                                                                                                                                                                 | Required test                           |
| ------------------------ | -------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------- |
| Manifest create          | App fact commits, then bot creation fails.                           | The create command plans all canonical facts and commits atomically where possible. If cross-aggregate work is required, an app state marks setup incomplete and a durable reconciler finishes or compensates it. The app cannot issue tokens while incomplete. | Failure after each setup step.          |
| One-step install         | Scope grant succeeds for some permissions, then another grant fails. | Calculate and validate the complete grant plan first. Commit bot permission and app install changes under explicit guards. Do not expose credentials before all grants are active.                                                                              | Inject each permission failure.         |
| Manifest update          | Two administrators update the same revision.                         | Manifest revision OCC accepts one update. The loser receives a revision conflict and the current export.                                                                                                                                                        | Concurrent updates.                     |
| Scope increase           | New manifest saves while the old install is active.                  | Preserve the definition, but keep the active grant generation unchanged until a new consent commits. Methods that need the new scope return `missing_scope`.                                                                                                    | Save, call, then reauthorize.           |
| Unknown key round-trip   | A known-field update occurs.                                         | Preserve unknown JSON or YAML data through normalized storage and export. Do not move or delete it.                                                                                                                                                             | Fixture with nested unknown keys.       |
| Request URL verification | Verification succeeds, but the save response is lost.                | Store verified URL hash and configuration generation. Exact retry returns verified state. A changed URL requires new verification.                                                                                                                              | Lost verification response.             |
| Uninstall                | Delivery and API calls race uninstall.                               | The installation generation fence stops new work. Work that passed authorization before commit follows the operation's request-time rule. Delivery attempts check current state again and suppress after uninstall.                                             | API and delivery races.                 |
| Reinstall                | Reinstall races delayed work from the old generation.                | New generation IDs are distinct. Old delivery and Socket claims cannot activate the new install.                                                                                                                                                                | Uninstall, reinstall, then old retry.   |
| Bot retirement           | Uninstall deactivates the bot while message history is read.         | Authorship and historical content stay readable under normal message authorization. No crypto-shredding occurs.                                                                                                                                                 | Read bot history after uninstall.       |
| App deletion             | Delete races install or update.                                      | App aggregate OCC selects one order. Permanent delete revokes every installation and blocks later update.                                                                                                                                                       | Delete/update and delete/install races. |

## API gateway and aliases

| Operation            | Failure or interleaving                                             | Required invariant and recovery                                                                                                                                                      | Required test                              |
| -------------------- | ------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------ |
| Method lookup        | Different case reaches the same method.                             | Normalize only for route lookup. Use the canonical registry name for scopes, metrics, rate keys, and response metadata.                                                              | Mixed-case calls.                          |
| Unsupported method   | An SDK invokes an unimplemented name.                               | Return an explicit method error and safe scope headers. Do not route by prefix to a different handler.                                                                               | Every unsupported registry entry.          |
| Input parsing        | Query and body supply the same argument with different values.      | Apply one documented precedence rule or reject the conflict. Never choose by map iteration order.                                                                                    | Query/form and query/JSON conflicts.       |
| Token placement      | Token appears in query or JSON.                                     | Reject the request before method handling. Do not log the query or body.                                                                                                             | Forbidden token locations.                 |
| Cursor use           | A cursor is replayed with a different method, app, user, or filter. | Authenticated cursor binding fails with `invalid_cursor`.                                                                                                                            | Cross-method and cross-principal replay.   |
| Rate limit           | Two replicas consume the final permit.                              | KV revision checks let one win. The loser returns HTTP 429 and `Retry-After`.                                                                                                        | Concurrent final permit.                   |
| Rate storage failure | The limiter cannot read or update shared state.                     | Fail closed with a temporary error. Do not use an uncoordinated local bucket.                                                                                                        | Inject KV outage.                          |
| Message alias        | Two messages have the same source microsecond.                      | EVT order assigns consecutive logical microseconds. Projection rebuild produces the same aliases.                                                                                    | Same-time concurrent posts and rebuild.    |
| Alias response       | The message commits before the alias projection catches up.         | Derive the alias from the committed event and sequence, then let the projection converge. Do not return a failure after the write commits only because the local projection is late. | Projection delay after commit.             |
| Alias lookup         | An app supplies an alias for a hidden message.                      | Return the same public not-found error as an unknown alias. Do not reveal existence.                                                                                                 | Hidden and unknown pairs.                  |
| Message post         | The canonical post commits, then the gateway response is lost.      | Reuse the result only when the caller supplied a stable request ID. Without one, a retry can create a second message. Do not deduplicate identical content.                          | Lost post response with and without an ID. |
| Message edit         | Permission changes during edit.                                     | Use the canonical edit consistency boundary. Return the committed result or current authorization error.                                                                             | Permission/edit race.                      |
| Delete then update   | Delete and update race from different replicas.                     | Room OCC selects one durable order. The loser returns the documented message error.                                                                                                  | Concurrent delete and update.              |

## Event materialization

| Operation            | Failure or interleaving                                                               | Required invariant and recovery                                                                                                   | Required test                    |
| -------------------- | ------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------- | -------------------------------- |
| Source commit        | A Chatto fact commits while no app worker is running.                                 | The durable EVT consumer discovers it after restart.                                                                              | Stop worker, commit, restart.    |
| Projection lag       | The materializer receives a fact before local authorization or app state includes it. | Wait through the source sequence before selecting targets. Do not infer from stale projections.                                   | Delay each required projection.  |
| Subscription change  | Subscribe, source event, and unsubscribe interleave.                                  | Active sequence intervals select the configuration at the source sequence. Current revocation can still suppress an HTTP attempt. | All sequence orders.             |
| Partial fanout       | Requests for some apps persist, then the materializer crashes.                        | Deterministic request IDs and unique-subject OCC make replay create only missing requests.                                        | Crash after each target.         |
| Unknown event schema | An older worker receives a new source branch.                                         | Do not acknowledge. The capable consumer generation handles it after rollout.                                                     | Mixed-version worker.            |
| Scope revocation     | Scope is revoked after request creation but before send.                              | The worker checks the current installation and suppresses the delivery.                                                           | Revoke before send.              |
| Membership loss      | Bot leaves or loses message read before send.                                         | Hydration returns no content. Record terminal suppression without payload data.                                                   | Leave and permission loss.       |
| Message deletion     | Message is retracted before send.                                                     | Do not deliver old plaintext. Record terminal suppression.                                                                        | Retract queued message.          |
| App self-event       | An app posts a message.                                                               | Apply the documented self-event rule from the event registry. Keep `app_id` and `bot_id` correct so SDK middleware works.         | Post with self-event on and off. |
| Event rate limit     | More than the per-app event allowance materializes.                                   | Suppress excess normal events and create one stable rate-limit event per minute.                                                  | Burst across replicas.           |

## HTTP delivery

| Operation                   | Failure or interleaving                                                          | Required invariant and recovery                                                                                                              | Required test                           |
| --------------------------- | -------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------- |
| Send accepted, outcome lost | The remote app returns 2xx, then the worker crashes before terminal persistence. | Redelivery can duplicate. Keep event and delivery IDs stable. Document at-least-once behavior.                                               | Crash after response.                   |
| Timeout                     | The remote app processes the body but exceeds three seconds.                     | Retry with the same event ID and incremented retry headers.                                                                                  | Slow accepting endpoint.                |
| Redirect                    | A destination redirects to a new host or private address.                        | Re-run URL and address policy for each redirect. Follow at most two.                                                                         | Public, private, loop, and long chains. |
| DNS rebinding               | DNS changes between validation and connect.                                      | Connect to the validated address without a second lookup. Validate the TLS host.                                                             | Rebinding test server.                  |
| No-retry response           | Non-2xx includes `X-Slack-No-Retry: 1`.                                          | Record terminal failure and stop.                                                                                                            | Each non-2xx class.                     |
| Retry schedule              | Worker restarts during delay.                                                    | Durable source time and attempt state reconstruct the next eligible time. Expired work resolves terminally.                                  | Restart at each delay.                  |
| Endpoint edit               | URL or secret generation changes during an in-flight request.                    | The in-flight request can finish with its captured generation. Later retries require the current generation and are cancelled if it changed. | Edit during send.                       |
| Endpoint revoke             | Revoke commits before connect.                                                   | Current-state check suppresses the request. A request already accepted by the remote app cannot be recalled.                                 | Revoke before and after connect.        |
| Auto-pause                  | Multiple replicas cross the failure threshold.                                   | App aggregate OCC records one pause generation. Later requests suppress.                                                                     | Concurrent threshold crossing.          |
| Signing                     | Body serialization changes after signature calculation.                          | Serialize once, sign those exact bytes, and send the same buffer.                                                                            | SDK verifier on raw bytes.              |
| Clock skew                  | Server time differs by more than the verifier window.                            | Health diagnostics flag skew. Do not widen signatures beyond the protocol window.                                                            | Positive and negative skew.             |

## Socket Mode

| Operation         | Failure or interleaving                                                   | Required invariant and recovery                                                                 | Required test                  |
| ----------------- | ------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------- | ------------------------------ |
| Connection ticket | Two clients use one URL.                                                  | One revision-matched consume wins. The other connection is rejected.                            | Concurrent ticket use.         |
| Connection count  | Two replicas open the tenth and eleventh connections.                     | Shared connection claims enforce a maximum of 10. One attempt fails.                            | Concurrent limit.              |
| Envelope claim    | Two active connections select one pending delivery.                       | One short revision-checked claim wins. The envelope goes to one connection at a time.           | Multi-connection claim.        |
| Ack lost          | Client sends an ack, then the connection drops before Chatto persists it. | The claim expires and the same envelope can be sent again. A repeated ack is idempotent.        | Drop after ack bytes.          |
| Process crash     | The connection owner dies with claimed envelopes.                         | Claims expire. Durable requests remain pending and another replica sends them.                  | Kill owner process.            |
| Token revoke      | An app-level token is revoked with live sockets.                          | Publish a disconnect hint and revalidate through the leader. All old-generation sockets close.  | Cross-replica revoke.          |
| Refresh           | Planned refresh overlaps a pending envelope.                              | Stop new claims, let the short drain window finish, then release unacked claims and disconnect. | Refresh with pending work.     |
| Ping timeout      | Ping or pong stops.                                                       | Close the connection and release claims. Do not mark an envelope terminal without an ack.       | Missing ping and missing pong. |

## Commands and interactions

| Operation             | Failure or interleaving                                             | Required invariant and recovery                                                                                                   | Required test                  |
| --------------------- | ------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------- | ------------------------------ |
| Three-second ack      | The app responds after the deadline.                                | The initiating user receives timeout UX. A valid late response can use the response URL if it remains active.                     | Responses around the boundary. |
| Trigger use           | Two view operations use one trigger ID.                             | One revision-matched consume wins. The other returns `trigger_exchanged`.                                                         | Concurrent use.                |
| Trigger expiry        | A request begins before expiry and commits after it.                | Expiry is checked in the consume operation. It returns `trigger_expired`.                                                         | Boundary clock test.           |
| Response URL count    | Two replicas use the fifth permit.                                  | One CAS update wins. The next use fails.                                                                                          | Concurrent fifth use.          |
| Response URL expiry   | Work starts before 30 minutes and posts after.                      | Check expiry at write time. Do not reserve an unbounded use.                                                                      | Delayed response.              |
| Permission revoke     | Bot permission is revoked after the original interaction.           | Late response fails current Chatto authorization. It does not use the earlier grant as permanent authority.                       | Revoke then respond.           |
| HTTP and Socket reply | The same interaction can receive a response through two transports. | One interaction response state accepts the first terminal action. Later conflicting actions fail or use the bounded response URL. | Dual response race.            |
| Options request       | App exceeds the three-second deadline.                              | Return an empty or timeout result according to the contract. Do not block the client surface.                                     | Slow options endpoint.         |

## Incoming webhooks and files

| Operation             | Failure or interleaving                                       | Required invariant and recovery                                                                                                                                                                          | Required test                                  |
| --------------------- | ------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------- |
| Webhook revoke        | A request authenticates on one replica while another revokes. | Recheck the credential generation through the leader before the message commit.                                                                                                                          | Revoke during post.                            |
| Webhook post response | Message commits, then response is lost.                       | The protocol has no idempotency key. A caller retry can create a second message. Do not merge identical bodies because legitimate repeated posts are valid. Document this at-least-once caller behavior. | Lost response with identical legitimate posts. |
| Bound room change     | App is reinstalled with another incoming webhook room.        | New credential generation uses the new room. Old URL cannot post to either room after revocation.                                                                                                        | Replace credential.                            |
| Upload URL            | Two clients upload to one URL.                                | Upload session offset and completion state select one byte sequence. Conflicting bytes fail.                                                                                                             | Concurrent upload.                             |
| Upload expiry         | Bytes arrive after session expiry.                            | Reject and clean partial bytes through existing upload cleanup.                                                                                                                                          | Expired upload.                                |
| File completion       | Message attachment commits, then response is lost.            | Exact completion retry returns the existing file and message. It never attaches twice.                                                                                                                   | Lost completion response.                      |
| File delete           | Download and deletion race.                                   | Current deletion fact makes new authorization fail. An already-open byte stream can finish according to existing asset behavior.                                                                         | Delete during download.                        |

## Rollout and rollback

| Operation              | Failure or interleaving                                                 | Required invariant and recovery                                                                                              | Required test                                |
| ---------------------- | ----------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------- |
| Expand rollout         | New readers and old readers run together before app writes are enabled. | No new app event is written. Existing Chatto behavior stays unchanged.                                                       | Mixed-version cluster with feature disabled. |
| Enable                 | One old replica remains when an app fact is about to commit.            | Activation check fails closed until every serving replica reports the event-schema capability.                               | Stale replica capability.                    |
| Rollback before writes | New binaries are removed before any app event commits.                  | Safe. No new durable contract exists.                                                                                        | Enable never used.                           |
| Rollback after writes  | A pre-feature binary starts after app events exist.                     | Startup must reject with a clear incompatible-schema error. Do not skip unknown domain facts.                                | Start old reader on new data.                |
| Consumer replacement   | A new materializer schema changes filters or output.                    | Use a new durable consumer generation. Drain or retire the old consumer explicitly.                                          | Parallel generations.                        |
| Backup and restore     | A backup contains pending delivery work.                                | Restore keeps request and consumer state, but immutable delivery deadlines prevent old external effects from becoming fresh. | Restore old backup.                          |

## Exit condition

A phase cannot claim multi-replica correctness until its relevant rows have
focused tests. A successful single-process test is not sufficient evidence.
